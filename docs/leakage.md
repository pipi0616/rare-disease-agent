# 防泄露：每个工具做了什么

这份文档讲清楚三件事：这个项目里"泄露"是什么、每个工具为了防泄露做了什么、我们怎么证明真的防住了。文中的例子全部来自真实的考题和真实的考试记录（dev-200，200 道题）。

---

## 一、什么是泄露，为什么它最要紧

### 泄露是怎么来的

我们的考题来自 Phenopacket Store。里面每个病人都出自一篇已发表的论文，论文里写了病人的症状和最后确诊的病。

工具查的资料库是 HPO。HPO 里每个病"常见哪些症状"，也是从论文里整理出来的，而且常常就是**同一批论文**。

所以会出现这种情况：考题出自论文 A，资料库里这个病的症状记录也来自论文 A。工具一查，等于直接看到了答案。

### 一个真实的例子

有一道题，病人有 4 个症状：窦性心动过缓、晕厥、多形性室性心动过速、尖端扭转型室速。正确答案是**病窦综合征 2 型**（OMIM:163800），病人出自论文 PMID:15123648。

在 HPO 里，这个病一共有 20 条症状记录，其中 **8 条就来自这篇论文**，比如：

- "窦性心动过缓 13/13"：13 个病人里 13 个有。这 13 个病人，就是这篇论文里的病人
- "尖端扭转型室速 1/1"：只有 1 个病人的记录，就是这篇论文里的那一个

结果：

| | 这个病排第几 |
|---|---|
| 不遮这篇论文 | **第 1 名** |
| 遮住这篇论文 | 第 35 名 |

不遮的时候排第 1，不是工具厉害，而是它查到的资料就是根据这个病人写的。

### 泄露有多普遍

- dev-200 的 200 道题里，有 **153 道**的正确答案，HPO 资料引用了这道题自己的论文
- 按症状排名这个工具，不遮的时候前 10 名能找对 **82.0%**，遮住以后只有 **49.0%**。差的 33 个百分点，全是"偷看答案"得来的

**如果不防泄露，所有分数都是假的**，后面做的比较也就全都没有意义。所以这是整个项目里最要紧的一件事。

## 二、总规则：三条

### 规则 1：考哪道题，就遮住哪道题的论文

考试程序在开始考一道题之前，先登记一句"这道题的论文是 PMID:xxx，遮住"。考完这道题，自动取消登记。

所有工具都去**同一个地方**读这条登记。工具自己不用记着要遮什么，所以不会出现"某个工具忘了遮"的情况。

模型完全不知道有这条登记，它看到的只是"资料就是这样"。

### 规则 2：只靠这篇论文的资料看不到，有别的论文支持的照常保留

还是病窦综合征 2 型那道题。这个病的 20 条症状记录里：

- 8 条只来自这道题的论文 → **遮住**
- 12 条来自别的论文（或者别的论文也报告过）→ **保留**

保留的那些记录，出处列表里**不再写这道题的论文号**，只写别的出处（这一点是 2026-10-09 修的，见第四节）。

### 规则 3：一个病如果只从这篇论文才知道，它就"不存在"

有些病，全世界只有这道题的论文描述过（往往这篇论文就是首次报告这个病）。遮住这篇论文以后，HPO 里关于它的记录一条都不剩。

对这种病，规则是：**考这道题的时候，它对所有工具都不存在。**

- 排名里不会出现它
- 按名字查不到它
- 去核对它、查它的资料，工具的回答和"这个编号根本不存在"一字不差。所以模型察觉不到有东西被藏起来了
- 讲它的疾病介绍搜不到，得这个病的其他病人也找不到

dev-200 里有 **40 道题**属于这种情况。

**为什么连名字都要藏？** 一个病如果只在这篇论文里描述过，那么它的名字本身就来自这篇论文。真实世界里，医生遇到"世界上第一个这样的病人"时，这个病还没有名字。

## 三、每个工具具体做了什么

### 工具 1：`rank_diseases`（按症状给所有病排名）

**它读什么**：HPO 里每个病的症状记录。

**怎么防**：

- 排名之前，先把"只来自这道题论文"的症状记录去掉，用剩下的记录给每个病重新算一遍（规则 2）
- 只从这篇论文才知道的病，直接不参加排名（规则 3）

**例子**：上面病窦综合征 2 型那道题，从第 1 名掉到第 35 名，就是这一步的效果。

### 工具 2：`lookup_disease`（查一个病的资料）

**它读什么**：一个病的症状和出现频率、遗传方式、发病年龄、致病基因、出处。

**怎么防**：

- 症状、遗传方式、发病年龄都只用遮住以后剩下的记录（规则 2）
- 出处列表里不写这道题的论文号
- 只从这篇论文才知道的病：回答"这个编号不是 HPO 里的病"，和查一个不存在的编号一模一样（规则 3）

### 工具 3：`check_match`（拿病人的症状逐条核对一个病）

**它读什么**：和工具 2 一样的症状记录。

**怎么防**：和工具 2 相同，三条规则都做到了。

**修过的问题**（真实例子）：一道题出自论文 PMID:37077559。agent 用 `check_match` 核对一个病时，回答里写着"下肢肌萎缩"这条症状的出处是 `['PMID:36454683', 'PMID:37077559']`，第二个就是这道题自己的论文。这条症状另一篇论文也报告过，按规则可以保留，但出处里不该写这道题的论文号。现在已经去掉了。

### 工具 4：`find_disease`（按病名查编号）

**它读什么**：所有病的名字。

**怎么防**：只从这道题论文才知道的病，按名字查不到（规则 3）。

**修过的问题**（真实例子，这是一个真漏洞）：有一道题，病人有肾小球肾炎、反复带状疱疹、MHC I 类分子表达降低。正确答案是 **MHC I 类缺陷 3 型**（OMIM:620814），HPO 里关于它的资料全部来自这道题自己的论文（PMID:12149238）。

我原来认为"病名不是从论文里来的知识，不用遮"，这个想法是错的。agent 在这道题里按名字查到了这个病，最后把它排在第 3 名。修之前，200 道题里这种"按名字查到了只从本篇论文才知道的病"的情况出现过 7 次（在 3 道题里），其中这 1 次让正确答案进了前 10 名。现在已经修了：这种病按名字查不到。

### 工具 5：`find_similar_patients`（找相似的已发表病人）

**它读什么**：Phenopacket Store 里已发表的病人，每人都有确诊的病和出处论文。

**怎么防**：

1. **这道题论文里的病人全部不找**：包括这道题的病人本人，以及同一篇论文里的其他病人（常常是一家人）
2. **得"只从本篇论文才知道的病"的病人也不找**（规则 3）
3. **病例库里只放 design 那一半的病人**：留出集（最后才考一次的那份题）的病人一个都不放，开发阶段每次考试都碰不到它们

**例子**：有一道题出自论文 PMID:27939403，正确答案是常见变异型免疫缺陷 13 型。这篇论文在病例库里有 9 个病人。考这道题时，工具在 6,005 人里找，不是 6,014 人，那 9 个人被藏起来了。找到的最像的 5 个病人都得这个病，来自另外三篇论文（PMID:31069201、33855675、31057532）。这是合法的：别的论文报告的病人，本来就是已经公开的知识。

### 工具 6：`search_disease_texts`（查疾病介绍，RAG）

**它读什么**：Orphanet 和 MedlinePlus 写的疾病介绍，切成 7,790 段。

**难点**：疾病介绍**不注明出处**，没法像 HPO 那样按论文遮。

**怎么防**：按"知识从哪来"推断。如果一个病在 HPO 里的资料全部来自这道题的论文，那它的疾病介绍多半也是根据这篇论文写的，所以一起遮住（规则 3）。遮挡在检索这一步就生效：哪怕直接拿介绍的原文去搜，也搜不到。

**例子**：有一道题出自论文 PMID:27087320，正确答案是一种神经发育障碍（OMIM:616975，全名"伴或不伴脑、眼或心脏异常的神经发育障碍"）。MedlinePlus 有一整页介绍这个病，可 HPO 里关于它的资料全部来自这道题的论文。考这道题时，这页介绍搜不到。dev-200 里有 2 道题是这种情况。

### 工具 7：`rank_candidate_genes`（看基因检测结果）

**它读什么**：HPO 的"基因–疾病"表（来自 OMIM），哪个基因会导致哪些病。

**怎么防**：

- 规则 3 也管这张表：一个病如果只从这道题的论文才知道，那么"这个基因导致这个病"这条知识也不用。往往正是这篇论文第一次发现了这个基因和这个病的关系
- 一个基因的病如果全被去掉，它就显示成"没有已知疾病"，和医生第一次遇到这种病人时看到的一样

**例子**：有一道题，正确答案是 MHC I 类缺陷 3 型（就是工具 4 里那道题），致病基因是 TAPBP，出自论文 PMID:12149238。HPO 关于这个病的资料只来自这篇论文，所以考这道题时，工具把 TAPBP 列在"没有已知疾病"那一栏，不会告诉 agent 它和 MHC I 类缺陷有关。

dev-200 里这样的题一共 40 道：

- 30 道的真基因显示为"没有已知疾病"
- 另外 10 道的真基因还关联着别的病（有别的论文记载），所以照样被打分。但正确答案那个病对所有工具都不存在，agent 拿不到它，所以不算泄露

**基因考法本身的防线**：这种考法会给每道题配一份"基因检测结果"：50 个候选基因，1 个是真的，49 个是假的。真基因就在名单里，这是故意的，真实的测序结果也是这样。为了不让名单本身漏答案：

- 名单按字母排序：真基因排在第几个，不透露任何信息
- 和这道题的病有关的其他基因不当假基因：免得出现"假基因其实也对"
- 每道题的名单用题目编号做随机种子：每次考试都是同一份
- 这是另一种考试（多给了一份信息），单独记录、单独报告，**从不拿来和只看症状的分数比**

### agent 和固定流程

它们自己不读资料，只通过上面这些工具查，所以工具的防线就是它们的防线。另外：

- **它们看到的题目只有性别和症状**（症状的名字和 HPO 编号；基因考法里再加一份候选基因名单）。没有诊断、没有致病基因，也没有题目编号。题目编号长这样：`PMID_12149238_Individual_SM`，里面带着论文号，所以绝对不能给模型看。我检查过，题目交给模型时不带编号
- 有一条测试专门检查：agent 调用工具时，遮挡确实生效

## 四、考试本身的防线

除了工具，考试的设计本身也在防泄露：

| 防线 | 做法 | 防的是什么 |
|---|---|---|
| 题目里不放答案 | 交给系统的只有性别和症状；答案单独存，只有判分的时候用 | 系统直接读到答案 |
| 按论文分开练习卷和正式卷 | 同一篇论文的病人，要么都在开发集，要么都在留出集 | 一家人一个在练习卷、一个在正式卷 |
| 练习卷每篇论文只出一道题 | dev-200 的 200 道题来自 200 篇不同的论文 | 同一篇论文的病人互相"提示" |
| 留出集只考一次 | 考留出集必须加 `--final`；病例库也不放留出集的病人 | 反复用正式卷调参 |
| "最常见的病"基线 | 只用开发集以外的论文来统计哪些病最常见 | 拿考题本身算"常见" |
| 基因考法单独报告 | 单独的实验（`eval/dev-200+genes`）和数据集；候选名单的规则有版本号 | 拿多给了信息的考试冒充进步；新旧名单混用 |

## 五、怎么证明真的防住了：四层检查

### 第 1 层：测试（30 条）

每个工具都有"遮住以后看不到"的测试，每次提交代码都会自动跑。比如：

- 遮住论文以后，只从这篇论文才知道的病不参加排名
- 遮住以后，这种病按名字查不到；而遮住别的论文时，照样查得到
- 一条症状另有出处时保留，但出处里不写被遮住的论文
- 同时考很多道题（并行）时，每道题只遮自己的论文，不会串
- 题目记录里不放答案

### 第 2 层：每次考完自动审计（2026-10-09 新加）

考完以后，程序把记录里**每一个工具的每一次回答**都读一遍，数两样：

1. 有没有出现这道题自己的论文号
2. 有没有出现"只从这篇论文才知道的病"

两个数都记进 MLflow，**必须都是 0**。不是 0 的话，这次考试会被标成"审计失败"，命令行直接报错："do not use these numbers"（这些数字不能用）。

论文号的匹配是精确的：PMID:10 不会被当成 PMID:1，有测试专门检查。

**这一层就是这次查出问题的那一层。** 第一次审计（翻第 15 章 agent 在 dev-200 上的考试记录）查出：

| 工具 | 调用次数 | 回答里出现这道题的论文号 | 回答里出现只从本篇才知道的病 |
|---|---|---|---|
| rank_diseases | 202 | 0 | 0 |
| check_match | 1,759 | 82 次（在 79 道题里） | 1 次 |
| lookup_disease | 271 | 58 次（在 58 道题里） | 1 次 |
| find_disease | 809 | 0 | 7 次（在 3 道题里） |

（第一次数的时候我把每次调用数了两遍：追踪记录里，每次工具调用会记两层，一层是 LangChain 的，一层是我们工具自己的。上表是每次调用只算一次的准确数字。另外，那次考试里 agent 还没有"找相似病人"工具；它在后来 20 道题的试跑里被查过，干净。）

**审计自己也有过盲区**（也是真实发生的）：修完以后先在 20 道题上验证，"找相似病人"和"查疾病介绍"两个基线显示"审计通过"，可"读了多少次工具回答"那一栏是 **0**。原因是这两个基线绕过了记录，直接调用工具内部的函数，追踪里根本没有工具的回答，审计没东西可读，"通过"是空的。

修法有两条：

1. 这两个基线现在也把读过的东西（每个病人的诊断、基因、出处论文；每段介绍讲的病和出处）记进追踪，和别的系统一样接受审计
2. 一个工具回答都没读到的考试，审计结果不再写"通过"，改写"没有工具回答可查"。比如"大模型直接猜"本来就不用工具，就会显示这一句。这样"通过"只表示真的查过、而且干净

修复以后，四个不用模型的基线在 dev-200 上重新考，审计结果见第七节。

### 第 3 层：遮和不遮各考一次

按症状排名这个工具，不遮 82.0%，遮了 49.0%。这说明遮挡确实起作用，也量出了泄露的分量。

### 第 4 层：人工抽查记录

每道题每一步调了什么工具、工具回答了什么，MLflow 里都存着，随时可以打开看（第 08、09 章讲过怎么看）。

## 六、还遮不住的（老实说）

这几条要写进结论里，不能藏。

### 1. 大模型自己的记忆（最大的一条）

DeepSeek 训练的时候，很可能读过这些论文。它脑子里记住的东西，工具层面没法遮。

**例子**：有一道题的正确答案是真性小眼球 2 型（Nanophthalmos 2，OMIM:609549），HPO 里关于它的资料只来自这道题自己的论文。"大模型直接猜"（不给任何工具）把它排在第 2 名。这可能是记得这篇论文，也可能只是从症状"眼球小"顺着病名猜出来的，分不清。

"大模型直接猜"整体能到 14.5%（第 1 名），可以看作它记住了多少的一个参考。

**真正的办法**：只用模型训练截止之后才发表的病例来考，它不可能读过。这放在第 6 步（大规模评测）。

### 2. 几篇论文合成一条的频率

**例子**：线粒体复合物 IV 缺陷（核型 2）有一条症状记录"血乳酸升高 9/10"，同时引用了 8 篇论文，其中一篇是某道题自己的论文。按规则 2，这条有别的论文支持，所以保留。但"9/10"这个数字里，可能包含这道题那篇论文的病人，拆不开。影响很小：只是频率数字，症状本身别的论文也报告过。

### 3. 同一个病人在另一篇论文里又被报告一次

我们按论文号遮。如果同一个病人后来在另一篇论文里又被写了一次，论文号不同，就认不出来。

**查了一下**：dev-200 里有 2 道题，在别的论文里能找到一模一样的病人（同一个病、同一组症状）：

- 一道是晶状体异位（只有 2 个症状）。症状这么少，很可能只是巧合，不是同一个人
- 另一道是常染色体显性肾小管间质性肾病，5 个症状完全一样，有可能是同一家人被报告了两次

最多影响 2 道题（1%）。

### 4. 疾病介绍里的细节

一个病如果有好几篇论文，它的疾病介绍可能也用了这道题论文里的内容。这和规则 2 的标准一致：有别的论文支持的知识照常保留。

### 5. 标注习惯相似（不算泄露，但会让结果偏好）

病例库和考题都是 Phenopacket Store 的人按同一套习惯标注的，所以"找相似病人"在我们的题上可能比真实世界里更准。医生自己写的症状，用词会更乱。这一点写在第 17 章和 README 里。

### 6. 基因考法是模拟的（不算泄露，但要说清楚）

我们的数据只记了真基因，没有完整的测序结果，所以 49 个假基因是模拟的：从已知会致病的基因里均匀随机抽。真实的测序结果里，更容易出现很长、很容易变异的基因；而且真实报告还会写出具体的变异、杂合还是纯合、致病性评分，我们只给了基因名。所以基因考法的分数只能说明"在这种模拟下"能做到多少，每次报告都要写明。

修复以后，四个不用模型的基线在 dev-200 上重新考了一遍（2026-10-09），每次考完都自动审计：

|---|---|---|---|---|
| 按症状排名 | 200 | 0 | 0 | 通过 |
| 排名后再核对 | 6,200 | 0 | 0 | 通过 |
| 找相似病人 | 200 | 0 | 0 | 通过 |
| 查疾病介绍 | 200 | 0 | 0 | 通过 |
| 按基因排名（基因考法） | 200 | 0 | 0 | 通过 |

带模型的 agent 在 20 道题上试跑了三次（带全部工具、两次带基因），审计都通过，每次读了 1,258 到 1,276 次工具回答。

分数的变化：

- 按症状排名、排名后再核对：**一点没变**（19.0% / 49.0%，30.5% / 54.5%）。它们本来就看不到"只从本篇才知道的病"，修复只是把出处列表收拾干净
- 找相似病人：前 10 名从 47.5% 变成 **46.5%**（少了 2 道题）。这 2 道题我逐个查过：
  - 一道是早发性癫痫 3 型（OMIM:620465），出自 2022 年的论文 PMID:36074901。HPO 关于这个病的资料只引用了这篇论文，所以按规则 3，它"不存在"。可是 Phenopacket Store 里还有另外两篇论文报告过这个病的病人（PMID:33190975、37161035），其中一篇是 2020 年的，比这道题的论文还早
  - 另一道是第三节工具 6 里那个神经发育障碍（OMIM:616975），别的论文（PMID:29330883）也报告过病人

  也就是说，在这 2 道题上我们**遮多了**：别的论文是独立发表的，那些病人本来可以用。原因是 HPO 没有收录那几篇论文，"只从本篇论文才知道"是按 HPO 的出处来判断的，HPO 漏收一篇，我们就会多遮一个病。我选择保留这个偏严的规则：遮多了，只是分数低一点；漏了，分数就是假的
- 带模型的系统（固定流程、agent）要花钱重考，留到第 20 章大考，到时候所有系统都在同一套规则下、带着审计重考

以后每一次考试，命令行最后都会打印一行审计结果，比如：

```
leak audit passed: 6,200 tool outputs read; own paper shown 0, diseases known only from it shown 0
```

不是 0 的话，命令直接报错，告诉你这次的数字不能用。

## 面试怎么说

> "Leakage was the first thing I designed against: HPO curates many disease annotations from the very papers the test cases come from — 153 of 200 dev cases — and the phenotype tool scores 82% unmasked against 49% masked. During evaluation each case's paper is masked through one context variable every tool reads; a disease known only from that paper does not exist for any tool, and the error says so in the same words as for any unknown id. After every run the harness reads back every tool output and fails the run if one shows the case's paper or such a disease. The first audit found two real gaps — the name search and source lists — and they were fixed. What cannot be masked is the model's own memory of the papers; that needs a temporal holdout."
