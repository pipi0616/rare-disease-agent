# 罕见病诊断 Agent：总体计划

## 1. 一句话

给一个病人的症状（和可选的测序结果），agent 自己决定查什么，找出最可能的罕见病和致病基因，每个结论都附证据；然后在严格防泄漏的公开病例上，和传统方法、固定流程、DeepRare 比较。

## 2. 架构

```
输入：症状描述 / HPO 列表（+ 可选：候选变异）
        |
        v
[编排层] Agent（DeepSeek，function calling，LangGraph 编排）
   循环：想下一步 -> 调一个工具 -> 读结果 -> 更新候选诊断 -> 够了就停
   结束前：逐条复核每个候选诊断的证据
        |
        v
[工具层] 每个工具单独可测，后期包成 MCP 服务
   T1 症状标准化      自由文本 -> HPO 术语
   T2 症状 -> 疾病排序  按 HPO 注释给所有罕见病打分（传统方法）
   T3 疾病知识        某个病的典型症状、遗传方式、致病基因
   T4 症状吻合度核对   病人症状 vs 某病症状：对上的、缺的、矛盾的
   T5 文献检索        PubMed，自动屏蔽病例的来源文献
   T6 变异证据        频率、致病性预测、ACMG 证据（复用 OtoVCE 的判据层）
        |
        v
输出：前 5 个诊断（疾病 + 基因）+ 每条的证据和出处 + 下一步建议做的检查
```

评测层和 agent 分开：读病例、防泄漏设置、自动判分、统计成本。

不做的：相似病例检索（不是推理必需，且最容易泄漏答案）。

## 3. 数据与验证（不需要医生）

- Phenopacket Store：本地 10,377 例，已发表病例，带确诊疾病、致病变异、来源 PMID。
- RareBench 公开子集：MME 40、HMS 88、LIRICAL 370、RAMEDIS 624。
- 判分：预测的疾病编号与确诊编号比对（OMIM / Orphanet / Mondo 互相映射），指标 Recall@1、@3、@5。
- 严格防泄漏：屏蔽来源文献；只用模型训练截止之后发表的病例做补充测试。
- 分层：按 Orphanet 患病率分"相对常见 / 超罕见"。

## 4. 对照组

| 编号 | 方法 | 作用 |
|---|---|---|
| B0 | 传统方法：只用 T2 打分 | 不用大模型的基线 |
| B1 | 单次调用大模型 | 不用工具的基线 |
| B2 | 固定流程：T1→T2→T3→T4，最后大模型汇总 | 回答"为什么要 agent" |
| B3 | 我们的 agent | 主角 |
| B4 | DeepRare | 已发表的强对照（原文数字 + 在公开子集上复跑） |

## 5. 里程碑（每一步都能演示）

| 步骤 | 内容 | 能演示的结果 |
|---|---|---|
| M1 | 评测底座：环境、读 50 例病例、自动判分；跑 B1 | 第一个数字：大模型直接猜的准确率 |
| M2 | 工具 T1–T4，每个配测试；跑 B0、B2 | 传统方法和固定流程的准确率 |
| M3 | Agent 编排（LangGraph）+ 轨迹可视化（本地 HTML）；跑 B3 | agent 每一步调了什么、为什么 |
| M4 | 加入基因型：T6 + 合成外显子（1000 Genomes 背景 + 致病变异） | 有基因数据时的准确率 |
| M5 | 严格防泄漏、患病率分层、DeepRare 对照；全量评测 | 论文主表 |
| M6 | 论文、README、面试材料；可选：小模型 SFT/GRPO | 交付 |
