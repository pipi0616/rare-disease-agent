# 正式评测方案（留出集）

> 这份方案**在留出集上跑任何东西之前**写好并提交。考完以后只在最后一节"结果"里填数字，前面的内容不再改。这样做是为了保证：看哪个指标、和谁比、怎么算赢，都不是看了结果以后才挑的。
>
> 写于 2026-10-13。

## 1. 为什么要有这一步

到第 20 章为止，所有分数都来自 dev-200 这 200 道题。可我们的每一个决定（留哪个工具、删哪个、提示词怎么改）都是看着这 200 道题的分数做的，所以那些分数偏乐观。

留出集从项目第一天起就单独放着：4,360 个病人，来自 840 篇论文，和开发用的病人没有任何一篇论文重合，从来没有任何系统在上面跑过。系统定稿以后在它上面**只考一次**，那个分数才是能对外说的。

## 2. 考哪些题

**`evals/splits/heldout-papers.tsv`：留出集的每篇论文各抽一道，共 840 道。**

- 抽法和 dev-200 一样：一篇论文一道，用固定的随机种子。有的论文一篇就报了 80 个病人，全考的话，同一家人的同一种表现会被反复数很多遍
- 清单已经生成并提交，校验码 `66892f26ff12050910986d004f61a8d428be84440f9e7720a431c5f05f1be5a3`
- 840 道题，479 种病。误差范围约正负 3 个百分点（dev-200 是正负 7）
- 其中 **119 道（14.2%）的病只在题目自己的论文里描述过**，另有 3 道的病 HPO 里没有记录。按防泄露的规则，这 122 道任何工具都答不对，所以只看症状时，满分大约是 85%
- 839 道有致病基因；基因考法用这 839 道

## 5. 事先定好：看什么，怎么算赢

**指标**：确诊的病出现在答案第 1 名、前 10 名的比例，带 95% 置信区间（Wilson）。两个系统比较时，在同一批题上逐题比，用双侧符号检验，p < 0.05 算显著。

### 主要结论（只有一个）

> **只看症状时，最终 agent 的第 1 名命中率是否高于固定流程。**

- 逐题比，最终 agent 对、固定流程错的题，显著多于反过来的 → **agent 更强**，成立
- 不显著 → 如实报告"在留出集上没有证明 agent 比固定流程强"，不改口径

### 次要结论（都会报告，不管结果好坏）

1. 只看症状，前 10 名：最终 agent 对固定流程
2. 只看症状，第 1 名：最终 agent 对传统方法、对大模型直接猜
3. 基因考法，第 1 名：最终 agent（已和基因排名合并）对不用模型的基因排名
4. 每个系统的第 1、3、5、10 名命中率和置信区间
5. 每个系统的花费和每道题用时

### 分开看的分析（事先说明是探索性的，不用来下主要结论）

- **能答的题和注定答不对的题分开算**：去掉那 122 道以后，各系统的命中率
- **按论文发表年份分**：大模型训练截止之前和之后发表的病例，分数差多少。这能看出"模型记住了论文"占了多少分

## 6. 规矩

**只在下面三种情况下，一次考试作废并重考：**

1. 记录不完整（记下来的题数和应考的不一样）
2. 有题目因为模型接口故障没答出来（欠费、限流、超时）
3. 泄露审计没通过

这三种都是程序自动判断的，和分数高低无关。作废的考试，分数不看、不用。如果是第 3 种，先修好泄露，写明改了什么，再重考。

**不许做的事：**

- 考完以后不改系统再考一遍。以后系统有改动，就是新版本，分数另外报告；`v1.0` 在留出集上的分数永远是这一次的
- 不挑着报：上面列的每一项都报，包括不好看的
- 不因为分数不理想就换指标、换题、换比较对象

**这次不包括的**（留到以后，用同一份 840 道题）：和 Exomiser、LIRICAL、PubCaseFinder、通用大模型、DeepRare 的比较；RareBench 数据集。

## 7. 我的预期（写在考之前）

dev-200 上：最终 agent 40.5% / 58.5%，固定流程 35.5% / 54.5%，逐题比 12 比 2。

留出集上我预计：

- 各系统的绝对分数和 dev-200 差不多，可能略高，因为注定答不对的题少一些（14% 对 20%）
- agent 对固定流程的领先会缩小：dev-200 上的 5 个百分点里，有一部分是我们看着这 200 道题调出来的。**如果领先缩到 2–3 个百分点，840 道题仍然可能测得出来；如果消失，就如实报告**
- 基因考法的合并（67.0%）是定稿前最后才加的，在 dev-200 上只验证过一次，是最可能缩水的一项

## 8. 结果

> 2026-10-13 考完后填写。第 1–7 节是考前写的，没有改动（git 记录可查）。详细过程见 `docs/notebook/21_heldout.ipynb`。
