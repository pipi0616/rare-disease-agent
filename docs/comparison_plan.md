## 1. 要回答的问题

第 21 章回答的是"我们的 agent 比我们自己做的对照系统强不强"。别人还会问另一个问题：

> **和已经发表、大家在用的诊断工具比，怎么样？**

对照系统是我们自己写的，写得弱一点，agent 就显得强。和一个别人做的、公认的工具比，才能回答这个问题。

## 2. 比谁，为什么

**LIRICAL 2.4.1**，只看症状的模式，默认设置。

- 杰克逊实验室做的罕见病诊断工具（Robinson 等，2020 年发表），做 HPO 的就是这个团队，一直在维护
- 能在本机离线运行，能只看症状
- 方法和我们的不一样：我们的排名工具算的是"语义相似度"，它算的是"似然比"（每个症状，这个病比一般的病多见多少倍）

**这一轮不比的，以及原因：**

| 工具 | 为什么这一轮不比 |
|---|---|
| Exomiser | 要读病人的测序文件（VCF）。我们的病例没有测序文件，只有致病基因的名字 |
| PubCaseFinder、Phenomizer、PhenoBrain | 是网站。它们的资料库里有这些已发表的病例，我们没法替它们遮掉，比出来不公平；请求也要发到外面去 |
| Phen2Gene | 排的是基因，不是病；它的知识库也没法遮 |
| 通用大模型（GPT、Claude、Gemini）、DeepRare | 要花钱，单独定方案和预算。DeepRare 还会上网搜索、查病例库，泄露问题要单独处理 |

## 3. 怎样才算公平

LIRICAL 拿到的东西，和我们每一个系统拿到的完全一样：

| | |
|---|---|
| 题目 | `evals/splits/heldout-papers.tsv`，840 道，和第 21 章同一份（校验码 `66892f26…1be5a3`） |
| 给它看什么 | 病人有的表现，加性别。**不给**"病人没有的表现"（对所有系统都不给：那是泄露，见 `docs/leakage.md`），不给年龄 |
| 知识库 | 同一版 HPO（2026-09-01）。核对过：LIRICAL 自己下载的 `phenotype.hpoa` 和我们固定的那一份，校验码完全相同 |
| 遮挡 | 每道题给 LIRICAL 单独写一份 `phenotype.hpoa`，按同样的三条规则遮掉这道题自己的论文：只靠这篇论文的记录删掉；别的文献也支持的记录保留；只在这篇论文里描述过的病整个删掉 |
| 答案范围 | 只算它给出的 OMIM 疾病（它另外还给 47 个 DECIPHER 条目打分，我们的题里没有这类答案） |
| 判分 | 同一个判分程序；前 10 名按 LIRICAL 自己排的顺序取 |
| 设置 | 默认设置，一个参数都不调 |

**接入是在 ci-20 和 dev-200 上调通的**，没有碰留出集。

**两处如实说明的改动：**

1. LIRICAL 2.4.1 读 HGNC 当前的基因名录会在启动时崩溃（有 3 对基因共用一个 Ensembl 编号）。我们删掉了重复的 3 行。核对过：基因名录不影响只看症状的排名（把名录砍到只剩 200 行，排名一字不差）
2. 给 Java 加了两个省 CPU 的启动参数。核对过：输出完全相同

## 5. 事先定好：看什么，怎么算赢

**指标**和第 21 章相同：确诊的病在第 1 名、前 10 名的比例，带 95% 置信区间；两个系统在同一批题上逐题比，双侧符号检验，p < 0.05 算显著。

### 主要结论（只有一个）

> **同样遮挡的条件下，最终 agent 的第 1 名命中率是否高于 LIRICAL。**

- 显著高 → agent 更强，成立
- 不显著，或者 LIRICAL 更高 → 如实报告，不改口径

### 次要结论（都会报告，不管好坏）

1. 同样遮挡，前 10 名：agent 对 LIRICAL
2. 同样遮挡：LIRICAL 对我们两个不用模型的系统（传统方法；先排名再逐条核对）。也就是：别人的成熟工具，比我们自己写的对照强不强
3. **LIRICAL 不遮对遮**：差多少。这个差就是"病人自己的论文在知识库里"带来的分数
4. 我们两个不用模型的系统，不遮对遮：差多少
5. 去掉注定答不对的 122 道以后，各系统的命中率

### 探索性的（不用来下结论）

- 只有 LIRICAL 答对、agent 没答对的题有多少。多的话，说明把 LIRICAL 当成 agent 的一个工具可能有用。这次只看，不改系统
